# Остаточные находки ревью — feat/sng-1-karkas

Ревью кода 03.09.2026 (correctness, testing, security, reliability, adversarial; кросс-модельный проход не запускался — в процесс не входит). Три подтверждённые находки применены в ветке. Ниже — то, что осталось и адресовано следующим задачам.

## Проверяется только живым токеном

- Завершение — это `checked: 1`, а не `complete`; формат `start` у задач без времени (`useTime: false`) — date-only даст ложную просрочку в зонах западнее UTC; сохраняет ли отложенная (`deferred`) задача `start`; отдаёт ли сервер `deleteDate` при `includeRemoved=true` с разреженным `fields`; `start` у генератора повторяющихся задач.
- Предупреждение о срезе по `maxCount` ненадёжно: при `includeAllRecurrenceInstances=false` сервер пост-фильтрует, и ответ может быть короче лимита при реальном срезе. Пагинации по `offset` нет.

## Сервис (SNG-2/SNG-4 — потребители появятся там)

- `FileView.watchChanges` (Quickshell 0.3.1): появление, атомарная замена и удаление файла ловятся не всегда — страховка: перечитывание на каждом тике таймера и при IPC `refresh`. Задержка до десяти минут.
- Ошибка `/v2/project` пишется в `errorText`, следующий удачный инкремент её стирает; кэш проектов остаётся пустым до смены суток или ручного `refresh` — отдельного признака в `status()` нет (reliability). Решить в SNG-3 вместе с экраном настроек.
- `mkdirProc`/`chmodProc` без обработки кода выхода: провал `mkdir -p` или `chmod 600` не виден пользователю.
- Если `curl` не стартовал (`FailedToStart`), `exited` не приходит и `inFlight` остаётся `true` — Timer-сторож на 30 с.
- Токен с последовательностью `\n` из двух символов: `curl` разворачивает её внутри кавычек конфига; источник — собственный файл 600. Закрыть — добавить обратный слэш в фильтр.
- `modifiedSince` по часам клиента с запасом в минуту; уход часов вперёд больше чем на минуту теряет правки до смены суток.

## Тесты

- Автомат состояний `Service.qml` не покрыт автотестами: QML вне `node --test`. Вынос `dayKey`, решения о полной выборке и quiet-гейта в `Api.mjs` сделал бы их тестируемыми.
- Нет тестов: `localOffset`/`endOfDay` для отрицательных и получасовых смещений; date-only `start`; `incrementalQuery` с числом на входе; порядок сортировки `merge` (тест нормализует id через `.sort()`); умолчания `normalizeTask` для нечисловых полей; экранирование `&`/`#` в `buildUrl`; фильтр токена (в QML).
- CI не проверяет загрузку QML (KTD7): синтаксическая ошибка в `.qml` даст зелёный пайплайн — проверка в оболочке после каждого MR.
