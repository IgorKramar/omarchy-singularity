# Тест оперся на локаль машины

## Проблема

Тест проверял, что после изменения названия задачи слияние отдаёт новый массив, и брал
изменённую задачу **по позиции**: `changed[0].title`. Позицию при равном начале решает
сортировка по названию — `a.title.localeCompare(b.title)`.

`localeCompare` без явной локали берёт локаль среды. В тесте сравнивались «иначе» и «task»:
кириллица против латиницы. На машине разработчика один порядок, на раннере CI (локаль `C`) —
другой.

## Симптомы

Тест зелёный локально, красный на CI, код тот же. В отчёте — `'task' !== 'иначе'`, то есть
на первом месте оказалась не та задача. Остальные сто тестов проходят, и это сбивает: выглядит
как случайность, а не как класс.

## Что не сработало

Прогон локально — сколько угодно раз. Локаль на машине одна, и результат воспроизводился
устойчиво зелёным. Разница видна только там, где локаль другая.

## Решение

Искать по идентификатору, а не по позиции, и не смешивать алфавиты в тестовых данных:

```js
// было — позиция зависит от локали
assert.equal(changed[0].title, "иначе")

// стало — id не зависит ни от чего
assert.equal(changed.find((t) => t.id === "A").title, "renamed")
```

Проверять в нескольких локалях, а не только в своей:

```bash
node --test test/api.test.mjs                 # родная
LC_ALL=C LANG=C node --test test/api.test.mjs # как на раннере
```

## Почему это работает

Сортировка по локали для **плагина** правильна: пользователь ждёт, что список упорядочен по
его алфавиту, и `localeCompare` это и делает. Менять код было бы ошибкой — неверен был тест,
принявший локаль своей машины за свойство мира.

Идентификатор — единственное в задаче, что не зависит ни от локали, ни от порядка ответа
сервера. Проверка через него говорит ровно то, что проверяется («эта задача обновилась»), и
не тащит за собой утверждение о порядке, которого тест не проверял.

## Профилактика

- **Не адресовать элемент по позиции там, где порядок задаёт сравнение строк.** Найти по id
  — на символ длиннее, а зависимости не создаёт.
- **Не смешивать алфавиты в фикстурах**, если тест не про сортировку. Два латинских названия
  сравниваются одинаково в любой локали.
- **Прогонять с `LC_ALL=C` перед отправкой**, если в проекте есть `localeCompare`,
  `toLocaleDateString`, `Intl` или сортировка строк. Это одна лишняя команда, и она заменяет
  круг «отправил — упало — разобрался».
- **Красный CI при зелёном локальном прогоне — сигнал о среде, а не о коде.** Первым делом
  сравнивать не логику, а окружение: локаль, часовой пояс, версию среды выполнения.

Родственный случай в этом же плагине, в другую сторону: движок QML **игнорирует** опции
`Intl`, которые понимает node. Форматирование даты внутри чистой функции печатало на экране
«04.09.2026», пока тест читал «4 сентября» и проходил (см. комментарий у `taskFields` в
`Api.mjs` и `formatField` в `TaskDetails.qml`). Там среда теста оказалась богаче среды
исполнения, здесь — просто другой; общее то, что **машина разработчика не эталон ни в одну
сторону**.
