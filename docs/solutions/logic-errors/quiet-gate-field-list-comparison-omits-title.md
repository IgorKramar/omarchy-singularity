# Список полей в сравнении «изменилось ли» — это перечисление того, что рисует потребитель

## Problem

Тихий гейт (`CONCEPTS.md`, раздел «Тихий гейт») держится на том, что построитель значения возвращает **прежнюю ссылку**, когда содержательно ничего не изменилось. У попапа этот ответ даёт `sameGroups` (`Api.mjs:266–277`): она проходит по секциям и решает, считать ли новую разметку той же самой. До правки сравнивались четыре свойства — `key`, `hidden`, `count` и тождество задач.

`title` в этот список не входил. Переименуйте проект в вебе — идентификатор тот же, задачи те же, счётчик тот же, меняется только строка заголовка. Гейт отвечает «ничего не двигалось», `groupByProject` (`Api.mjs:280–283`) отдаёт прежний массив, и попап рисует старое название проекта — `Panel.qml:432` берёт текст заголовка ровно из `modelData.title`. Держится это, пока живёт панель: `root.view` — её собственное свойство (`Panel.qml:48`), обновляемое через `rebuild()` (`Panel.qml:66–68`), то есть до перезапуска оболочки.

Предыдущая запись — [`quiet-gate-identity-check-outside-pure-function.md`](./quiet-gate-identity-check-outside-pure-function.md) — чинила **где** живёт решение о равенстве: в чистой функции, куда дотягивается `node --test`, а не в QML, куда не дотягивается ничто. Здесь решение стояло уже в правильном месте, было покрыто тестами и всё равно было неверным. Общая форма: **сравнение, отвечающее «ничего не изменилось», — это список полей, который ведут руками, и он обязан перечислять всё, что рисует потребитель.** Поле, которое потребитель рисует, а сравнение не упоминает, замерзает — видимо, правдоподобно и молча.

## Symptoms

- **Попап показывает старое название проекта** при верном составе и верных счётчиках. Отличить устаревшее имя от актуального на экране невозможно: ошибочное состояние выглядит в точности как исправное.
- **Само расколдовывается от постороннего.** `sameGroups` сравнивает разметку целиком, поэтому любая правка, задевшая одно из четырёх сравниваемых полей в **любой** секции — закрытая задача, новая задача, ушедшая из окна, — перестраивает массив, и название обновляется вместе со всем остальным. Диагноз «переименование не доезжает» отсюда не следует никогда.
- **56 тестов зелёные.** Число сверено по срезу до правки (`git show 23d28f7:test/api.test.mjs`, 56 вызовов `test(`); после правки — 65, все проходят.
- **Второй дефект той же формы, найденный тем же проходом:** `isCollapsed` (`Api.mjs:312–315`) читала одно множество ключей с **противоположной полярностью** в зависимости от `group.hidden` — скрытая секция по умолчанию свёрнута, обычная развёрнута. Одна и та же запись `P-2` означала «развёрнута» для одной и «свёрнута» для другой. Разверните серую отсеянную секцию, уберите проект из списка исключаемых — и секция закроется сама, без единого действия пользователя.

## What Didn't Work

- **Тесты ссылочной стабильности — по одному на функцию, и все написаны намеренно.** `groupByProject` (`test/api.test.mjs:350`), `hiddenGroups` (`:374`), `flattenGroups` (`:402`), `popupView` (`:451`). Каждый варьировал **набор задач**; отдельный тест варьировал **часы** (`:479`, «новые сутки меняют разметку просрочки при тех же задачах»). Ни один не варьировал название проекта. Ось «название» не была осью, о которой кто-то думал, — а поле, забытое сравнением, ровно то, о котором не вспоминает и тест.
- **Правило уровня плана было соблюдено.** KD8 (`docs/plans/2026-09-04-003-feat-sng-3-popap-plan.md:45`) и KTD5 (`:211`) требовали, чтобы разрез, группировка и вычисление скрытого набора жили чистыми функциями в `Api.mjs`, — и они там живут. Урок предыдущей записи был усвоен и не помог: он про местоположение решения, а не про его содержание.
- **Покрытие строк не показывало ничего.** Строка `a.every(...)` исполнялась в каждом тесте, который трогал попап. Дефект — в том, чего в этой строке **нет**; такого покрытие не видит ни при какой полноте.
- **Взгляд на экран.** Устаревшее название проекта неотличимо от актуального, если не помнить, как проект назывался пять минут назад.

Нашло это ревью кода: по записи коммита `323c0c4` проход шёл семью линзами. Три линзы — корректность, тесты и состязательный проход — назвали эту находку каждая у себя, и состязательная воспроизвела её по коду с полной уверенностью, без запуска оболочки. (Коммит свидетельствует только число линз и то, что три находки прохода подтверждены независимо; какие именно линзы совпали на этой, известно из самого прогона, а не из записи.) Независимость контекстов и есть то, что сделало дефект видимым: одна линза, глядящая на `sameGroups`, видит корректный код — он делает ровно то, что написано.

## Solution

```js
// Api.mjs:266–277
function sameGroups(a, b) {
  if (!Array.isArray(a) || a.length !== b.length) return false
  return a.every((g, i) => g.key === b[i].key && g.title === b[i].title
    && g.hidden === b[i].hidden && g.count === b[i].count
    && g.tasks.length === b[i].tasks.length
    && g.tasks.every((t, j) => t === b[i].tasks[j]))
}
```

Добавлены две вещи, и вторая — не косметика.

**`title`** закрывает сам дефект: заголовок теперь участвует в решении о равенстве наравне с тем, что под ним нарисовано.

**Явное сравнение `g.tasks.length`** заменяет опору на инвариант, который держится в другом месте файла. Длина массива задач и раньше сравнивалась — через `count`, которое `buildGroups` присваивает отдельным проходом (`Api.mjs:260`). Пока инвариант «`count` равен `tasks.length`» верен, сравнение работает; но оно верно не по построению, а по совпадению, и держится на строке, до которой один рефакторинг. **Сравнение, опирающееся на инвариант, поддерживаемый где-то ещё, — это сравнение, которое сломается молча.** Заодно это чинило и настоящую дыру: `a.every` по задачам без сверки длин ничего не сказал бы про хвост более длинного массива.

Полярность сворачивания вынесена в отдельную функцию:

```js
// Api.mjs:308–315
export function toggleKey(group) {
  return (group.hidden ? "h:" : "p:") + group.key
}

export function isCollapsed(group, toggled) {
  const has = (Array.isArray(toggled) ? toggled : []).includes(toggleKey(group))
  return group.hidden ? !has : has
}
```

Запись в хранимом множестве теперь несёт **умолчание, от которого отступили**: `p:P-2` значит «обычную секцию свернули», `h:P-2` — «скрытую развернули». Когда проект переходит границу отсева, старая запись просто перестаёт совпадать, и секция возвращается к своему умолчанию вместо того, чтобы перевернуться. QML переключает секцию через ту же функцию (`Panel.qml:226–233`) и берёт состояние через `isCollapsed` (`Panel.qml:380`) — в QML не осталось ни одного самостоятельного суждения о полярности.

Тесты выросли с 56 до 65. Четыре из новых закрывают именно эти два места:

```js
// test/api.test.mjs:517 — та самая ось, которую не варьировал никто
test("groupByProject замечает переименование проекта при неизменном наборе задач", () => {
  const tasks = [t("A", { projectId: "P-2" })]
  const first = groupByProject(null, tasks, projectsFixture)
  assert.equal(first[0].title, "Дача")
  const renamed = [{ id: "P-1", title: "Работа" }, { id: "P-2", title: "Огород" }]
  const second = groupByProject(first, tasks, renamed)
  assert.notEqual(second, first, "переименование обязано перестроить секции")
  assert.equal(second[0].title, "Огород")
})

// test/api.test.mjs:546 — флаг hidden меняется, запись в множестве остаётся
test("isCollapsed: проект, вышедший из отсева, не переворачивает свою секцию", () => {
  const secret = { key: "P-2", hidden: true }
  const toggled = [toggleKey(secret)]
  assert.equal(isCollapsed(secret, toggled), false, "развёрнута, как и просили")
  const plain = { key: "P-2", hidden: false }
  assert.equal(isCollapsed(plain, toggled), false,
    "обычная секция по умолчанию развёрнута; прежняя запись не должна её сворачивать")
})
```

Второй тест — про переименование скрытой секции (`:529`) — существует потому, что `hiddenGroups` (`Api.mjs:288–298`) вызывает ту же `sameGroups` со своим `prev`: один дефект давал два места проявления, и починка одного не доказывает починку второго.

## Why This Works

**У тихого гейта два отказа, и они противоположны по цене.**

Ложноположительный — гейт говорит «изменилось», когда не изменилось. Это дефект SNG-2: лишние перерисовки, ни одно показанное значение не искажено. Ловится счётчиком событий на неизменном входе, что предыдущая запись и закрепила прогоном из четырёх пересчётов.

Ложноотрицательный — гейт говорит «не изменилось», когда изменилось. Это дефект здесь. Перерисовок нет, потому что перерисовывать по мнению гейта нечего, и **вред уходит прямо в показанное значение**: пользователь читает неверный текст. Никакой счётчик событий этого не увидит — событий и не должно быть много. Единственная проверка — сверка списка сравниваемых полей с тем, что рисует потребитель.

Почему `title` выпал именно он, а не что-то другое, видно из устройства построителя. `buildGroups` (`Api.mjs:249–262`) принимает **два** входа: задачи и кэш проектов. Кэш проектов влияет на результат двумя разными способами — определяет, известен ли проект (и значит, какой будет `key`, `Api.mjs:249`), и даёт текст заголовка (`Api.mjs:249`). Сравнение представляло первый способ и не представляло второй. Все остальные поля группы либо сравнивались, либо выводятся из сравниваемого: `kind` — чистая функция `key` (`Api.mjs:250`), `hidden` приходит аргументом, `count` — длина `tasks`. **Замерзает то поле, которое зависит от входа, не представленного в сравнении ни одним слагаемым.**

С полярностью то же самое, но по другой оси. `isCollapsed` до правки читала ключ, не зависящий от `hidden`, и применяла к нему отрицание, зависящее от `hidden`. Это не забытое поле, а забытая **привязка**: смысл записи определялся тем, чего в самой записи нет. Пока `hidden` у секции не менялся, всё было верно — а меняется он ровно от той настройки, ради которой отсев и существует.

Общее у обоих: правильность держалась на условии, которого в коде не написано (`count` равен длине; `hidden` не меняется), и оба условия ломает не рефакторинг, а обычное пользование.

## Prevention

**Полнота списка полей проверяется чтением, и проверка конечна.** Взять конструктор значения — здесь литерал в `buildGroups` (`Api.mjs:247–253`) — и для каждого поля ответить одним из трёх: сравнивается напрямую; выводится из сравниваемого (тогда назвать, из какого); потребителем не читается (тогда назвать, чем это установлено — `group.kind` сегодня не читает ни один из пяти QML-файлов плагина: поиск по слову `kind` находит `row.kind` от `flattenGroups` и `kind` у результата `footerState`, обращений к полю секции нет ни одного, как нет и построения имени поля во время работы). Ответа «наверное, покрыто» не бывает. Более короткая версия того же вопроса: **каждый вход построителя представлен в сравнении?** Именно на нём дефект и виден — `projects` был представлен наполовину.

**Ось теста ссылочной стабильности — вход, а не функция.** «По тесту на функцию» и «по тесту на поле» — разные покрытия, и первое выглядит как второе. Пять тестов стабильности покрывали четыре функции и варьировали два входа из трёх. Правило, дающее конечный список: для каждого входа построителя — тест «меняем только его, всё остальное держим тем же; ссылка обязана смениться». Число таких тестов равно числу входов и не зависит от того, сколько функций эти входы обходят. Предыдущая запись сдвинула ось с «есть ли тест» на «на каком пути стоит тест»; эта сдвигает её с «на какой функции» на «по какому входу».

**Хранимый флаг, читаемый с двумя умолчаниями, хранит умолчание вместе с собой.** Признак класса замечается механически: чтение вида `условие ? !x : x`, где условие берётся из данных, а ключ хранения от этих данных не зависит. Либо ключ включает то, от чего зависит чтение (`toggleKey`), либо множеств два. Одно множество и два умолчания — договор, который держится, пока данные не переехали через границу.

**Дешёвой автоматики, ловящей это, нет — но есть дешёвая механизация половины риска.** Ревью предложило собирать возвращаемый объект первым и сравнивать его целиком, а не вести список полей руками; это оставлено резидуалом (`docs/residual-review-findings/feat-sng-3-popap.md`, п. 8) с причиной: перестраивать гейт в том же коммите, где чинится дефект гейта, рискованнее, чем не перестраивать. Стоит понимать, что именно такая перестройка даёт и чего не даёт. Она снимает риск «добавили поле в объект и забыли в сравнение» — новое поле попадает в сравнение само. Она **не** снимает риск «сравнили не тем видом равенства»: для задач нужна проверка тождества элементов, для заголовка — сравнение строк, и этот выбор всё равно делает человек. Тот же список полей руками ведёт `popupView` (`Api.mjs:384–387`) — там он длиннее и продублирован рядом с возвращаемым объектом, то есть расхождение будет видно глазами. У `sameGroups` такого соседства нет: сравнение и построение стоят в разных функциях, и это ровно то, что сделало пропуск незаметным.

**Признак момента, когда всё это надо доставать.** Между источником и потребителем стоит гейт по ссылке, и у построителя больше одного входа. Тогда любой вход, влияющий только на текст — название, метка, форматирование, — самый вероятный кандидат на пропуск: он ни на что не влияет структурно, поэтому не попадает ни в сравнение, ни в тест, ни в диагноз по симптому.
