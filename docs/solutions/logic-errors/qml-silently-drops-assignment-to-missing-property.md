# QML молча принимает присваивание несуществующему свойству

## Проблема

Чтобы удержанный `Space` не отмечал задачи одну за другой, в объявление перехватчика клавиш было добавлено:

```qml
PanelKeyCatcher {
  Keys.ignoreAutoRepeat: true   // такого свойства не существует
}
```

Строка выглядит рабочей, читается однозначно и не делает ничего. У прикреплённого объекта `Keys` есть `enabled`, `forwardTo` и `priority` — `ignoreAutoRepeat` там нет (оно живёт у `Shortcut` и у `MouseArea`).

## Симптомы

Ничего. Оболочка грузится, попап открывается, список рисуется. Отличить это состояние от исправного нельзя ни по экрану, ни по поведению — кроме того самого случая, ради которого строка и писалась.

Проверки проекта тоже проходят: валидатор манифеста, `qmlformat` и `node --test` зелёные. Разбор здесь ни при чём — синтаксис верен, а вот свойства нет.

Единственный след — предупреждение в журнале **процесса оболочки**, не плагина:

```
WARN scene: .../Panel.qml[401:12]: Cannot assign to non-existent property "ignoreAutoRepeat"
```

## Что не сработало

Перезапуск оболочки и проверка глазами. Попап открывался, задачи рисовались — то есть все признаки успеха были на месте. Ошибка нашлась только когда журнал оболочки перестал читаться по диагонали и был перенаправлен в файл: `quickshell ... > /tmp/qs.log 2>&1`.

До этого журнал вообще не читался: `journalctl _PID=<pid>` по процессу оболочки не возвращает ничего, потому что она запускается не через systemd.

## Решение

Автоповтор здесь отличить нечем: сигнал перехватчика его не несёт, а собственный `Keys.onPressed` конфликтовал бы с тем, что уже объявлен внутри `PanelKeyCatcher`. Поэтому — защёлка по времени в обработчике:

```qml
onActivateRequested: {
  var row = root.cursorRow
  if (row && row.kind === "task") {
    var now = Date.now()
    if (now - root.lastKeyCompleteAt < 400) return
    root.lastKeyCompleteAt = now
    root.completeTask(row.task)
  }
}
```

## Почему это работает

Защёлка не пытается опознать автоповтор — она опирается на то, что человек не целится в две разные задачи с интервалом в четверть секунды. Свойство, которого нет, заменено свойством времени, которое есть.

Более общий вывод — про сам класс ошибки. **Присваивание несуществующему свойству в QML не является ошибкой разбора.** Файл грузится, объект создаётся, всё остальное работает. Это тот же класс, что и «правило записано, а признак его действия никто не проверил»: успешный вызов инструмента не доказывает, что результат наступил.

## Профилактика

- **Журнал оболочки — обязательная часть живой проверки, а не запасной вариант.** Запускать так, чтобы он писался в файл, и просматривать его после каждой правки QML:
  ```bash
  setsid quickshell -n -p /usr/share/omarchy/shell > /tmp/qs.log 2>&1 &
  grep -i "<id плагина>" /tmp/qs.log | grep -vi IpcHandler
  ```
  Фильтр по идентификатору плагина отсекает чужой шум: в этом журнале десятки предупреждений от других плагинов, и своё в них теряется.
- **Незнакомое прикреплённое свойство сверяйте с исходником типа**, а не с памятью: `Keys`, `Layout`, `Drag` — у каждого свой набор, и по имени он не угадывается.
- **Признаком успеха считайте наблюдаемое следствие, а не отсутствие ошибки.** Здесь следствие проверяется удержанием клавиши, и именно это надо было сделать сразу, а не после того, как журнал показал предупреждение.
