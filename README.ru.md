Задачи [SingularityApp](https://singularity-app.com/) на рабочем столе [Omarchy](https://omarchy.org/): счётчик в баре, список по проектам и управление с клавиатуры.

> **Статус: в разработке.** Счётчик, попап и фоновый сервис работают. В попапе можно завершать, переименовывать и добавлять задачи. Полноэкранный оверлей ещё не реализован.

## Возможности и планы

| Поверхность | Тип | Содержание |
|:---|:---|:---|
| Пилюля в баре | `bar-widget` | Количество сегодняшних и просроченных задач |
| Попап | `bar-widget` | Задачи по проектам, три вкладки, клавиатурное управление, завершение / переименование / добавление |
| Оверлей — в планах | `overlay` | Полноэкранные колонки «Просрочено / Сегодня / Завтра», чек-листы, привычки и учёт времени |

Токен, опрос API и кеш принадлежат фоновому `service`. Виджет показывает его состояние; будущий оверлей должен использовать тот же источник данных.

## Попап

Нажмите на пилюлю, чтобы открыть список задач, сгруппированных в сворачиваемые секции по проектам. Закрыть его можно повторным нажатием или `Esc`. Управление через оболочку:

```bash
omarchy-shell singularity.popup toggle   # также: open, close, show, hide
```

IPC-цель `singularity.popup` отделена от сервисной `singularity`: первая управляет окном и не передаёт названия задач или кеш. На нескольких мониторах попап открывается на активном выходе.

Вкладки **Сегодня**, **Все**, **Просрочено** — срезы одного кеша. Переключение не вызывает новый запрос. «Все» означает всё окно задач, которое учитывает пилюля. Просрочка пересчитывается по текущему времени: открытый через полночь попап не полагается на вчерашний флаг из ответа.

Сервис получает всё окно задач каждые десять минут независимо от того, открыт ли попап. Поэтому изменения с телефона или из веб-приложения появляются при следующем успешном опросе. Открытие попапа запрашивает обновление раньше, если с последней синхронизации прошло больше минуты. Внизу видны состояние обновления и время последнего успешного запроса.

Исключённые из счётчика проекты не исчезают: они остаются приглушёнными свёрнутыми секциями. Их можно раскрыть, не изменяя счётчик. Подвал показывает число скрытых **задач**.

### Действия над задачей

Нажатие на чекбокс или `Space` завершает выбранную задачу. Нажатие на строку или `Enter` открывает её заметку, заполненные поля и ссылку в веб-приложение. Одновременно раскрыта одна задача.

Пока API не подтвердит изменение, строка остаётся на месте с отметкой отправки. Ошибка записи показывается внизу, не удаляет задачу и не превращает весь сервис в состояние сбоя.

**`u` отменяет последнее завершение.** Подвал называет задачу, которую вернёт команда. Отмена одношаговая: это не полная история изменений.

**У повторяющейся задачи вместо чекбокса — знак повтора.** Генератор и его экземпляры являются разными объектами SingularityApp; завершение экземпляра через используемый API недоступно, поэтому плагин не предлагает такое действие.

`e` превращает название в поле с выделенным текстом. `n` переводит фокус в поле новой задачи внизу списка; задача попадёт во «Входящие» с сегодняшней датой. В обоих полях текст сохраняется до подтверждения сервера, чтобы после ошибки можно было повторить отправку. `Esc` выходит из редактирования без отправки.

### Клавиатура

| Клавиша | Действие |
|:---|:---|
| `↑` `↓` `k` `j` | Перемещение между задачами и заголовками секций |
| `←` `→` `h` `l` | Переключение вкладок |
| `Enter` | Раскрыть секцию или выбранную задачу |
| `Space` | Завершить задачу; на заголовке — свернуть / раскрыть секцию |
| `e` `у` | Переименовать задачу |
| `n` `т` | Перейти к полю новой задачи |
| `o` `щ` | Открыть проект задачи в веб-приложении |
| `u` `г` | Отменить последнее завершение |
| `Tab` `Shift+Tab` | Перейти к соседней панели бара |
| `Esc` | Выйти из поля или закрыть попап |

Буквенные команды поддерживают кириллические клавиши по той же позиции. Переключение вкладок закреплено за горизонтальными клавишами, а `Tab` сохраняет привычный для оболочки переход между панелями. Сворачивание секций выполняет `Enter`.

Выбор привязан к задаче, а не номеру строки: появление новой задачи выше не сдвигает его. Если выбранная задача покидает окно, выбирается следующая в её секции, затем предыдущая, затем заголовок секции.

## Требования

- Оболочка Omarchy с API плагинов `schemaVersion: 1`.
- Тариф SingularityApp **Pro** или **Elite**, предоставляющий REST API.
- API-токен из веб-приложения с правами *Task* на чтение и запись; дополнительные категории — *Project*, *Habit*, *Checklist*, *Tag*, *Time statistics*.

## Установка

```bash
omarchy plugin add https://github.com/IgorKramar/omarchy-singularity.git
omarchy plugin enable io.github.igorkramar.singularity
```

`enable` добавляет виджет в раскладку бара; по той же записи оболочка запускает фоновый сервис. Для этого не требуется вручную добавлять ещё одну запись в `shell.json`.

### Токен

Токен читается из файла и передаётся `curl` через stdin, а не аргументы процесса. Создайте файл, вводя токен в скрытом приглашении:

```bash
dir=~/.local/state/omarchy/io.github.igorkramar.singularity
mkdir -p "$dir"
(umask 077; read -rsp 'Token: ' t; echo; printf '{"apiToken":"%s"}\n' "$t" > "$dir/settings.json")
```

Ввод через `read -s` не попадает в историю команд; `umask 077` создаёт новый файл с правами `600`. Сервис следит за файлом и подхватывает токен без перезапуска, а также ограничивает права до `600`.

```bash
omarchy-shell singularity status    # no-token | loading | ready | error, errorText, tasks и другие поля
omarchy-shell singularity refresh   # запросить данные сейчас
```

### Исключение проектов из счётчика

Проекты вроде дней рождения или праздников можно не учитывать в пилюле. Фильтр применяется в сервисе; попап получает то же отфильтрованное состояние, будущий оверлей должен использовать его же.

**В Omarchy нет встроенного экрана настроек плагина.** Основной способ — дополнить существующую запись виджета в `~/.config/omarchy/shell.json`:

```json
{ "id": "io.github.igorkramar.singularity",
  "excludedProjects": "Дни рождения, Праздники" }
```

Запись определяется полем `id`; не создавайте второй виджет вместо правки существующего. Оболочка отслеживает файл, изменения применяются без перезапуска. При нескольких мониторах все записи управляют одним сервисом, побеждает последняя загруженная: задайте им одинаковый `excludedProjects`.

Если установлен сторонний [plugin-control-center](https://github.com/brm-src/omarchy-plugin-control-center), можно использовать его форму настроек. Манифест содержит схему формы, но без этого плагина её некому отображать.

Проекты сопоставляются **по имени, не по ID**, без учёта регистра и пробелов по краям. Допустимы строка через запятую и JSON-массив.

- Переименование проекта отключает прежнее исключение: обновите имя в настройках.
- Совпадение исключает **все** одноимённые проекты.
- Исключение родителя **не исключает** подпроекты; перечислите их отдельно.

```bash
omarchy-shell singularity status                  # visibleCount, overdueCount, excludedProjects, filterApplied
omarchy-shell singularity exclude "Дни рождения"   # временная проверка фильтра
```

`status` содержит `tasks` — отфильтрованный список — и `allTasks` — всё окно. `exclude` **не сохраняется**: при следующем изменении настроек виджет снова передаст значение из `shell.json`.

Если список исключений задан, но кеш проектов ещё не загружен, `filterApplied` равен `false`: имена пока не разрешены и показан нефильтрованный счётчик. Подсказка пилюли сообщает об этом.

## Разработка

Из каталога клона создайте ссылку в каталог плагинов:

```bash
ln -sfn "$PWD" ~/.config/omarchy/plugins/io.github.igorkramar.singularity
omarchy plugin enable io.github.igorkramar.singularity
```

Оболочка перезагружает плагин при сохранении. Если изменение за симлинком не замечено, выполните `omarchy-shell shell rescanPlugins`.

Валидируйте **из исходного клона**, не через симлинк: валидатор отвергает ссылку как часть дерева плагина.

```bash
omarchy plugin validate "$PWD"
TZ=Asia/Omsk node --test test/api.test.mjs
```

В CI используются тесты чистого модуля `Api.mjs` и проверка манифеста с точками входа. Они **не исполняют QML**. Имя тестового файла указано явно, чтобы исчезновение файла не давало успешный прогон с нулём тестов. Часовой пояс закреплён для проверок дат.

`Api.mjs` — ES-модуль, общий для QML и Node. Для локальных QML-проверок нужен Qt 6; на среде разработки `qml` из `PATH` относится к Qt 5, поэтому используется `/usr/lib/qt6/bin/qml`.

Документация понятий: [CONCEPTS.md](CONCEPTS.md). Публичная спецификация API: <https://api.singularity-app.com/v2/api-json>.
