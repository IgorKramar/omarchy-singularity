# Concepts

Shared domain vocabulary for this project — entities, named processes, and status concepts with project-specific meaning. Seeded with core domain vocabulary, then accretes as ce-compound and ce-compound-refresh process learnings; direct edits are fine. Glossary only, not a spec or catch-all.

Словарь ведётся по-русски, как и записи в `docs/solutions/`, которым он служит подложкой.

## Опрос

### Сервис

Единственный владелец токена, опроса и кэша задач. Живой один на оболочку, а не один на монитор: экземпляров виджета бара столько, сколько экранов, но все они читают один и тот же сервис и своих запросов к API не делают.

Отсюда следствие, которое легко нарушить: любое состояние, влияющее на то, что видно во всех поверхностях, принадлежит сервису, а не виджету. Настройка, пришедшая от виджета, передаётся сервису и применяется там.

### Окно

Набор задач, который плагин показывает: незавершённые, не отложенные, с **заданным** началом не позже конца текущего **локального** дня. Задача без начала в окно не входит вовсе. Внутри окна задача считается просроченной, если её начало раньше начала текущего локального дня.

Локальность здесь — часть определения, а не деталь: API отдаёт время в UTC, и полночь по местному времени приходит как вечер предыдущих суток. Граница дня, вычисленная по текстовому представлению даты, промахивается на сутки.

### Полная выборка

Опрос, заменяющий кэш целиком. Может нести серверные ограничения окна, потому что выход задачи из окна ей безразличен — она строит набор заново. Делается принудительно на старте, при смене локальной даты и по ручному обновлению.

### Инкремент

Опрос «что изменилось с момента X», обновляющий кэш дельтой. **Серверных ограничений окна не несёт никогда**: сервер не вернёт задачу, которая перестала им удовлетворять, и выход из окна остался бы невидимым. Ограничение окна применяется на стороне клиента после слияния — одним и тем же предикатом для полной выборки и инкремента.

## Вид

### Тихий гейт

Правило, по которому сигнал об изменении испускается только тогда, когда опубликованный набор действительно изменился. Реализуется возвратом **прежней ссылки**: построитель значения, получив содержательно тот же результат, отдаёт обратно ровно тот объект, что был раньше, и потребитель узнаёт «ничего не изменилось» по тождеству.

Гейт существует потому, что опрос идёт постоянно и почти всегда вхолостую; без него каждая поверхность перерисовывалась бы на каждом тике.

Решение о равенстве принадлежит тому, кто строит значение, и никогда вызывающему: вызывающий не видит, по скольким путям построитель выделяет новый объект. Как только между источником и гейтом появляется ещё один шаг, тождество должен обеспечивать этот шаг, а не тот, кто его вызвал.

### Отсев проектов

Список названий проектов, задачи которых не идут в счёт. Применяется в сервисе, а не в счётчике, и потому действует на весь плагин: любая поверхность видит один и тот же набор.

Сопоставление идёт по названию, не по идентификатору, потому что список правится человеком в файле настроек. Отсюда три следствия: переименование проекта молча снимает с него отсев; правило срабатывает на всех одноимённых проектах разом; исключение родителя не наследуется подпроектами. Задача без проекта не отсеивается никогда.

### Полное окно и отсеянный вид

Два набора, которые сервис держит одновременно. Полное окно — то, что вернул опрос; отсеянный вид — то, что осталось после отсева проектов, и именно его читают поверхности.

Разделение обязательно: слияние инкремента идёт **по полному окну**. Слить дельту поверх отсеянного вида значило бы выбросить задачи исключённого проекта из кэша насовсем, и очистка отсева не вернула бы их до следующей полной выборки.

### Отсев не применён

Состояние, в котором список исключаемых задан, но сопоставить названия не с чем: кэш проектов ещё не пришёл. Считается отдельно от «отсев пуст», потому что в обоих случаях число получается неотсеянным, но в первом это временная неготовность, о которой надо сказать вслух, а во втором — норма.
